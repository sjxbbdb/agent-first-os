# 源码主线验收协议

验收证明的是“能理解、能改动、能复现、能迁移”，不是“看过视频”或“屏幕上出现过成功文字”。

## 一、每个源码单元的验收循环

~~~text
读前预测
  → 原始版本运行
  → 一处改动
  → 差异解释
  → 故障/负向路径
  → 口头复述
  → 迁移题
~~~

一个单元必须有一个可观察出口。没有运行证据的内容标记为 E 未验证；只有阅读推断不能写成通过。

## 二、Unit Gate

| 项目 | 通过表现 |
|---|---|
| 源码定位 | 能指出入口文件、符号、下一跳和边界 |
| 因果预测 | 运行前能预测寄存器、内存、对象状态或输出 |
| 原始运行 | 命令、环境、参数和完整输出可复现 |
| 单处改动 | 改动范围清楚，行为差异可解释 |
| 故障路径 | 至少一个故障真实发生，或明确标为推断 |
| 口头复述 | 不看源码说清输入、状态变化、不变量和返回 |
| 迁移题 | 换地址、参数、设备或调用顺序后仍能判断 |
| 设计映射 | 能说明对 Agent-First OS 保留、重写和不照搬什么 |

Unit Gate 通过后才更新能力等级；答对某一道题不会自动解锁整阶段。

## 三、阶段 Gate

每个 SF 阶段 100 分，建议达到 80 分；权限、隔离和恢复阶段的安全关键项不能为零。

| 项目 | 分值 | 证据 |
|---|---:|---|
| 调用链和概念解释 | 20 | 白板图、随机口试、逐行说明 |
| 独立实现或重建 | 25 | 关闭参考后完成指定变体 |
| 可复现运行 | 20 | 构建命令、QEMU 参数、串口/调试输出 |
| 改动和故障定位 | 15 | 一处差异、负向测试、根因说明 |
| 不变量和边界 | 10 | 地址、权限、回收、错误路径 |
| 迁移设计 | 10 | 外部样本到自研接口的映射 |

分数只辅助判断，关键出口缺失时不能用总分抵消。

## 四、源码阅读的随机检查

老师会从当前切片随机抽查：

- 这条指令执行前后哪些寄存器改变？
- 这次内存访问经过哪些页表和权限检查？
- 这个函数依赖哪个前置不变量？
- 删除这一行会出现什么故障？
- 哪一条日志、寄存器或反汇编能证明你的判断？
- 把地址、长度或调用者换掉，哪些结论仍然成立？

## 五、关键故障清单

| 单元 | 至少选择一个 |
|---|---|
| SF-01 启动 | 错签名、错扇区、栈未准备、错误跳转 |
| SF-02 内核机制 | 非法地址、时钟不进、错误 syscall、退出泄漏 |
| SF-03 x86_64 | 长模式条件失败、页表错误、IDT 错误、PIT 参数错误 |
| SF-04 内核骨架 | ELF 越界、BootInfo 版本错、OOM、page fault |
| SF-05 隔离和 IPC | 非法用户指针、伪造句柄、撤销后使用、超时 |
| SF-06 服务 | 服务崩溃、子进程逃逸、设备消失、重启失败 |
| SF-07 Agent | 恶意计划、窗口越权、token 重放、断网、取消 |
| SF-08 产品化 | UEFI map key 变化、坏模块、SMP 竞态、更新回滚 |

故障实验必须保存恢复步骤，不能为了产生故障破坏唯一工作副本。

## 六、证据包

每个完成的单元至少有：

~~~text
learning/notes/lesson-log/YYYY-MM-DD-SF-xx-topic.md
learning/evidence/SF-xx-*.md
learning/projects/<unit-or-topic>/
~~~

证据文件要区分：

- 事实：命令和日志实际显示的内容；
- 推断：根据源码或规范推测但尚未运行的内容；
- 未验证：当前环境无法证明的内容；
- 限制：工具链、QEMU、设备或许可证造成的边界。

产品区的 M0–M14/G0–G10 证据留在原位置，不能当作学员的 SF Gate 证据。

## 七、状态标签

统一使用：

~~~text
未开始   进行中   ✓ 已掌握   ↺ 需要巩固
! 概念更正   E 未验证   R 已完成迁移题   G 已通过阶段 Gate
~~~

当前单元只在 notes/PROGRESS.md 出现一次；历史记录通过索引链接，不覆盖旧结论。
