# Agent-First OS 学习与实现课程

## 课程目标

这是一套从计算机底层开始、最终能够独立设计和实现 Agent-First OS 的课程。目标不是把学员训练成某个教程的代码复读者，而是让学员能够：

- 解释 CPU、内存、固件、设备和程序之间的真实关系；
- 使用 C、x86_64 汇编、链接器和调试器构建裸机程序；
- 从零写出 BIOS 启动链，并为同一个内核增加 UEFI 启动路径；
- 实现内存、异常、中断、线程、进程、用户态、syscall 和 IPC；
- 设计 capability、Supervisor、用户态系统模块和混合内核；
- 实现文件、网络、窗口、键鼠和设备服务；
- 实现远程模型驱动的 agent、任务恢复、策略和可信确认；
- 通过日志、故障注入、代码解释和独立改动证明自己真的掌握了系统。

“理解每一条代码”在本课程中指：对我们自己编写的启动器、内核和用户态模块，能够说明每条关键代码的语义、硬件效果、不变量、失败后果和验证证据。外部项目只阅读与当前目标相关的源码和规范，不承诺把所有第三方仓库逐行读完。

## 课程工作方式

每个学习单元都按照同一个循环推进：

```text
目标 → 预测 CPU/内存状态 → 最小实现 → 运行验证
  → 故障注入 → 逐行解释 → 复盘 → 通过 Gate
```

每一课都会留下一个小产物，而不是连续数月只读理论。每次提交至少包含：

1. 源码和变更差异；
2. 可复现的构建和运行命令；
3. 串口日志、QEMU 参数、截图或调试输出；
4. 对不变量、故障现象和未验证部分的说明。

每个阶段都要求一次变体题、一次白板复现和一次源码寻错，防止只会照抄教程。

## 我会怎样教

课程不是把一大段成品代码交给学员，而是由我维护一张持续更新的课程状态表。每次只推进一个可验证单元：先讲硬件事实和问题，再让学员预测状态，随后给出最小实现任务。学员提交代码和证据后，我会逐行检查关键路径、指出边界问题、要求一次独立变体，并根据 Gate 决定补课、重做或进入下一单元。

外部教材按用途分工：教材负责概念，规范负责硬件和协议事实，课程实验负责对照，自己的代码负责最终设计。遇到冲突时，以当前硬件规范、工具输出和我们的实际运行证据为准。

教学过程始终保留三条互相衔接的循环：

```text
基础循环：C / 汇编 / 工具链 / 体系结构
内核循环：启动 / 内存 / 中断 / 进程 / IPC / capability
产品循环：服务 / 设备 / 安全 / 桌面 / agent / 远程模型
```

三条循环会交替推进，避免只学理论或只堆功能。每个阶段结束时，都要能解释“如果删掉这个机制会发生什么”，并能在新参数或新故障下迁移所学内容。

## 能力等级

| 等级 | 能力表现 |
|---|---|
| L0 | 能看懂术语和结构图，但无法预测运行结果 |
| L1 | 按模板复现并解释基本输出 |
| L2 | 能独立改参数、改接口并定位普通错误 |
| L3 | 能独立设计小模块、处理故障并给出证据链 |
| L4 | 能迁移到新设备或新约束，完成设计评审和教学说明 |

进入下一阶段通常要求相关能力达到 L3；安全、权限和恢复相关能力要求 L4。

## 阶段地图

### 阶段 0：工程与工具链基线

**目的**：建立可重复的开发环境，避免把环境错误误认为内核错误。

**子阶段**：

0.1 Windows、WSL、Linux 文件系统和命令行；  
0.2 Git、分支、差异、提交和回滚；  
0.3 Make/CMake、环境变量和可复现构建；  
0.4 NASM、GCC/Clang、Binutils、GDB、QEMU、OVMF；  
0.5 串口日志、退出码、磁盘镜像和 hexdump。

**能力**：能从空目录编译一个 freestanding C 程序，读取 ELF header 和 linker map，使用 GDB 观察寄存器。

**产物**：`hello-vm`、构建脚本、工具版本报告、最小证据目录。

**Gate**：能解释 `.text`、`.rodata`、`.data`、`.bss`、栈、堆和链接地址；能从日志复现一次构建失败。

### 阶段 1：C、机器码、链接与 ELF

**子阶段**：

1.1 指针、数组、结构体、位运算和内存布局；  
1.2 未定义行为、整数溢出、对齐和别名规则；  
1.3 编译、汇编、目标文件和链接；  
1.4 System V AMD64 调用约定、栈帧和寄存器保存；  
1.5 ELF header、program header、section、重定位和入口地址。

**能力**：能把 C 函数对应到汇编和栈变化，能解释编译器为什么需要 freestanding 选项。

**产物**：freestanding C 小库、ELF 查看器、栈帧和链接地址实验。

**Gate**：不看教程完成一个 ELF 段解析改动；能用 `objdump`、`readelf` 和 GDB 证明入口地址正确。

### 阶段 2：x86_64 体系结构

**子阶段**：

2.1 通用寄存器、RFLAGS、控制寄存器和 MSR；  
2.2 实模式、保护模式、长模式和特权级；  
2.3 GDT、IDT、TSS 和段寄存器；  
2.4 页表、TLB、NX、用户/内核页和地址规范；  
2.5 异常、中断、CPUID、APIC 和设备寄存器。

**能力**：能画出地址转换和异常路径，预测一条关键指令前后寄存器、页表和权限的变化。

**产物**：寄存器观察程序、页表实验、异常触发实验。

**Gate**：能解释错误页表为什么导致 page fault 或 triple fault；能区分普通函数调用、中断和系统调用。

### 阶段 3：操作系统理论与对照实验

**子阶段**：

3.1 进程、地址空间和虚拟化；  
3.2 调度、并发、锁和条件同步；  
3.3 I/O、持久化、文件系统和崩溃恢复；  
3.4 安全、认证、权限和隔离；  
3.5 用 Linux `strace`、`/proc`、`perf` 和小模拟器观察这些概念。

**能力**：能把 OSTEP 的抽象概念映射到实际内核机制，而不是只背定义。

**产物**：调度器模拟器、页替换模拟器、日志文件系统小实验、设计笔记。

**对照项目**：MIT xv6 用于理解进程、虚拟内存、文件系统和 syscall；它是 RISC-V 教学内核，不是我们的 x86_64 目标内核。

### 阶段 4：BIOS 自写启动链

**子阶段**：

4.1 512 字节启动扇区和 `0x55AA`；  
4.2 Stage 1 加载 Stage 2；  
4.3 BIOS 磁盘服务、LBA 和错误处理；  
4.4 A20、GDT 和 32 位保护模式；  
4.5 PAE、页表和 64 位长模式；  
4.6 ELF64 加载、BSS 清零和 BootInfo；  
4.7 跳转到 `kernel_entry()`。

**能力**：能从空磁盘镜像写出可启动的两阶段加载器，并使用 QEMU/GDB 定位启动失败。

**产物**：BIOS 启动镜像、Stage 1/Stage 2、ELF 加载器、版本化 BootInfo。

**故障注入**：破坏 `0x55AA`、错读扇区、越界加载、未建立页表、未对齐栈、错误长模式跳转。

### 阶段 5：UEFI 现代产品路径

**子阶段**：

5.1 UEFI 应用和 EFI System Partition；  
5.2 GPT、PE/COFF 和 UEFI 加载协议；  
5.3 GOP 帧缓冲；  
5.4 UEFI memory map 和 `ExitBootServices()`；  
5.5 ACPI RSDP、表结构和 AML 概念；  
5.6 让 UEFI 启动器复用同一个 ELF64 内核接口。

**能力**：能解释 BIOS 与 UEFI 的职责差异，能让两条启动路径交给同一个内核。

**产物**：OVMF 启动镜像、UEFI loader、GOP 输出和 BootInfo 对照测试。

### 阶段 6：单核内核核心

**子阶段**：

6.1 linker script 和内核布局；  
6.2 物理帧分配器；  
6.3 内核堆；  
6.4 恒等映射到高半内核；  
6.5 IDT、异常栈和 panic；  
6.6 时钟、PIT、LAPIC/虚拟 APIC；  
6.7 串口日志和内核观测。

**能力**：能解释一个虚拟地址如何经过页表变成物理地址，能处理 OOM、非法指针和 page fault。

**产物**：帧分配器、页映射器、高半内核、异常日志。

### 阶段 7：线程、进程、Ring 3 与 syscall

**子阶段**：

7.1 内核线程和上下文切换；  
7.2 栈、时钟抢占和单核调度；  
7.3 进程地址空间；  
7.4 Ring 3 进入和返回；  
7.5 静态 ELF64 用户程序加载；  
7.6 syscall ABI、用户指针验证、`copyin/copyout`；  
7.7 `exit/wait` 和资源回收。

**能力**：能画出用户态程序发起 syscall 到内核返回的完整链路。

**产物**：第一个 Ring 3 程序：输出文字并退出；多个用户程序交替运行。

**故障注入**：死循环、非法 syscall、非法用户指针、错误栈、退出时资源泄漏。

### 阶段 8：IPC、共享内存与 capability

**子阶段**：

8.1 同步 endpoint 和消息 ABI；  
8.2 超时、取消和错误返回；  
8.3 capability handle、权限位和对象生命周期；  
8.4 capability 转移、限制和撤销；  
8.5 共享内存映射、回收和大数据传输；  
8.6 TOCTOU、恶意长度和跨地址空间校验。

**能力**：能设计一个小而深的 IPC 接口，证明句柄不可伪造、权限可撤销。

**产物**：跨进程 ping-pong、共享内存通道、权限矩阵、fuzz/负向测试。

### 阶段 9：Supervisor 与混合内核服务

**子阶段**：

9.1 第一个用户态进程；  
9.2 服务 manifest、依赖 DAG 和启动顺序；  
9.3 心跳、健康检查和崩溃重启；  
9.4 任务进程组、冻结和资源回收；  
9.5 文件、进程、网络、窗口和输入服务的接口；  
9.6 agent 与系统服务的信任分层。

**能力**：能让一个用户态服务崩溃并自动恢复，同时保持其他服务和内核工作。

**产物**：Supervisor、服务注册表、重启策略、进程组和日志。

### 阶段 10：现代 PC 基础设备与系统服务

**子阶段**：

10.1 PCI/PCIe 枚举、BAR、MMIO 和中断；  
10.2 virtio-block、virtio-net 和 virtqueue；  
10.3 VFS、块缓存、日志和一致性；  
10.4 最小网络栈；  
10.5 GOP 帧缓冲；

**能力**：能把硬件能力包装为可重启、可审计的用户态服务。

**产物**：QEMU virtio 存储/网络、最小文件系统、显示和输入服务。

## 阶段通过标准

每阶段设置一个 Gate。建议总分达到 80/100，且安全关键项不能为零：

| 项目 | 分值 | 证据 |
|---|---:|---|
| 概念与口头解释 | 20 | 白板地址图、时序图、随机代码逐行解释 |
| 独立实现 | 30 | 关闭教程后完成指定变体 |
| 运行验收 | 20 | 命令、QEMU 参数、串口日志、退出码、截图 |
| 调试与故障注入 | 15 | 故意制造故障并解释根因和恢复 |
| 代码与架构审查 | 10 | 不变量、错误路径、回收、权限和可观测性 |
| 知识迁移 | 5 | 改设备、地址、调用场景后仍能完成 |

只看到“屏幕上显示成功”不算通过。每个结论必须附运行、源码或日志证据；没观察到的行为必须标记为未验证。
