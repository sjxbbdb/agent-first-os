# 教学闭环与记录协议

这套协议规定每一课如何开始、如何选择资料、如何验收、如何批改，以及哪些内容进入 GitHub。它和 `CURRICULUM.md` 的阶段地图、`STUDY_PLAN.md` 的资料路线、`ASSESSMENT.md` 的阶段 Gate 共同工作。

## 一课的固定流程

```text
查进度 → 宣布本课出口 → 判断讲解/网课/实验
  → 讲解与重点标记 → 学员笔记与预测
  → 练习或观看验收 → 复述与批改
  → 记录掌握状态 → 推送教学记录 → 解锁下一小节
```

每一课只设置一个主要出口。出口没有达到时，下一课先补当前缺口，不因为课程总纲的顺序而强行推进。

### 课前：老师决定用什么方式教

| 情况 | 主要方式 | 例子 |
|---|---|---|
| 新术语、简单因果、代码逐行理解 | 直接在会话中讲 | 变量、赋值、进制、进程状态 |
| 需要连续演示、中文讲解更顺 | 指定网课片段，再由老师验收 | C 基础、x86 启动、OS 概念 |
| 必须观察真实输出或硬件行为 | 本地实验 | 编译、ELF、QEMU、页表、syscall |
| 需要建立设计判断 | 会话讲解 + 对照资料 + 设计题 | 混合内核、capability、Supervisor |

老师每次布置网课时必须写清：课程入口、具体章节或分 P、观看目的、跳过范围、观看后的验收题。网课不是看完即通过。

### 课中：重点、笔记和互动

- `【重点】`：必须记进平板，并能在课后复述；
- `【易错】`：记录常见误解和一个反例；
- `【练习】`：先独立回答，再看讲解；
- `【复述】`：不看资料，用自己的话说明因果或流程。

每节课的笔记只保留少量核心结论、一个自己的例子、一个疑问和一个可观察证据。模板见 [NOTE_TEMPLATE.md](../notes/NOTE_TEMPLATE.md)。

### 课后：学员提交什么

概念课只需发送：

1. 平板笔记中标出的重点；
2. 练习答案和理由；
3. 不确定的地方。

网课课后增加：

1. 课程标题和实际观看章节；
2. 三条自己的笔记；
3. 一道闭卷复述题；
4. 一道改参数或换场景的迁移题。

代码实验课再增加：

1. 源码差异或 commit；
2. 构建、运行和调试命令；
3. 日志、截图或反汇编输出；
4. 一个故障注入及根因说明。

## 网课观看后的验收

老师不会要求学员复述视频的所有细节，而是检查四件事：

| 检查 | 通过表现 |
|---|---|
| 概念 | 用自己的话说明机制解决了什么问题 |
| 顺序 | 能画出或说出输入、处理、输出的先后关系 |
| 迁移 | 修改一个地址、参数、调用顺序或场景仍能判断结果 |
| 边界 | 能说出一个失败情况、错误后果和发现证据 |

四项中有一项明显缺失，就把该片段标记为“需补课”，不继续增加新视频。

## 作业批改方式

每份作业按下面的顺序批改：

1. 先看答案是否完成题目要求；
2. 再看理由是否真的说明了因果，而不是只写结论；
3. 对代码检查边界、命名、错误路径和可读性；
4. 对运行结果检查命令、环境和证据是否能复现；
5. 给出一项“保持”、一项“修正”、一项“下一次迁移”。

批改标签统一使用：

```text
✓ 已掌握       ↺ 需要巩固       ! 概念更正
E 未验证       R 已完成迁移题   G 已通过阶段 Gate
```

“答对”只说明这道题通过；只有在新例子或迁移题中仍然正确，才把能力写入 `PROGRESS.md` 的“已掌握”。

## 记录与推送规则

每次课结束后，老师更新四类记录：

| 记录 | 写入内容 | 文件 |
|---|---|---|
| 课后记录 | 本课目标、讲解、练习、答案、批改和下一步 | `learning/notes/lesson-log/` |
| 笔记索引 | 本课笔记入口、状态、待复习项 | `learning/notes/INDEX.md` |
| 能力进度 | 已验证能力、未验证能力、补强项、当前阶段 | `learning/notes/PROGRESS.md` |
| 课程联动 | 当前小节对应的阶段、资料和 Gate | `CURRICULUM.md` / `STUDY_PLAN.md` |

代码实验通过检查后，再把源码和证据放进 `learning/projects/` 与 `learning/evidence/`；通过阶段 Gate 后，才考虑复制或迁移到 `product/`。

每次推送使用一个说明清楚的 commit，提交信息包含“教学记录”或“阶段实验”和具体主题。推送前检查 Markdown 链接、敏感信息和 `git diff --check`。推送后把 commit 号写回课后记录。

## 阶段联动

每个阶段都维护一条链：

```text
阶段目标
  → 指定网课/规范章节
  → 会话补讲与重点笔记
  → 小练习/实验
  → 迁移题与故障注入
  → Gate 证据
  → 解锁下一个阶段
```

资料清单是候选池，`STUDY_PLAN.md` 是推荐路线，老师每次发出的课后任务才是当前唯一需要执行的范围。
