# 源码驱动教学闭环与记录协议

这份协议规定每个源码单元怎样开始、怎样读、怎样运行、怎样批改和怎样记录。课程总纲决定顺序，源码执行表决定当前出口，验收协议决定是否通过。

## 一、固定闭环

~~~text
读取当前指针
  → 宣布一个行为出口
  → 指定最小源码切片
  → 学员写预测
  → 原始版本运行
  → 一处改动再运行
  → 故障注入或负向路径
  → 逐行解释和口头复述
  → 老师批改
  → 更新记录并解锁下一单元
~~~

一个单元可以跨多个会话，但始终只保留一个主要出口。出口没有达到时，下一次先补这个缺口，不因为阶段表的编号强行前进。

## 二、老师和学员的分工

### 老师负责

- 选择当前调用链的最小文件和函数；
- 说明为什么读它、暂时跳过什么；
- 标出平板笔记的 【重点】、【易错】 和 【练习】；
- 在运行前收取预测，运行后对照证据；
- 只在当前问题需要时补 C、汇编、体系结构或规范；
- 批改代码、日志、迁移题和口头复述；
- 更新当前指针、能力状态、待补强项和下一单元。

### 学员负责

- 先读指定切片，不自行扩张到整棵仓库；
- 在运行前写出 CPU、内存、状态和输出预测；
- 原样保存命令和输出，错误也要保留；
- 每次只改一个变量、指令或接口；
- 按模板写笔记和课后复述；
- 不确定的内容标为未验证，不用猜测冒充事实；
- 把自己的实现与外部样本分开提交。

## 三、源码阅读协议

### 1. 选择切片

每个切片必须包含：

- 一个入口文件和入口符号；
- 一条不超过当前能力范围的调用链；
- 一个可观察行为；
- 一个可控改动点；
- 一个故障或边界条件。

### 2. 读前记录

在打开实现细节前先写：

- 入口怎样被调用；
- 关键寄存器、内存或对象状态是什么；
- 预期输出、返回码或下一跳；
- 哪个不变量应该保持；
- 如果猜错，最可能在哪里看到证据。

### 3. 运行和改动

先运行未改版本并保存原始证据，然后只改一处。改动可以是 marker、地址、长度、调度参数、权限位或错误分支，但要写明改动前预测。一次修改同时改变多个机制时，该单元不算清晰。

### 4. 故障和恢复

故障实验必须可恢复。优先选择错签名、错地址、非法参数、超时、越权句柄、服务退出等边界。记录现象、根因、发现证据和恢复命令；没有真正运行过的故障写成“推断”，不能写成“通过”。

### 5. 解释标准

逐行解释至少包含：

- 这行读取或写入什么；
- 对 CPU、内存或对象状态造成什么变化；
- 依赖哪个前置不变量；
- 删除或改错后会出现什么；
- 哪条日志、寄存器或反汇编可以证明。

## 四、网课和资料的使用

网课不再是默认主线。只有下面几种情况才指定片段：

- 当前源码出现尚未学过的语法；
- 连续寄存器或硬件动作需要演示；
- 错误信息需要背景概念；
- 需要查证规范，而不是凭印象判断。

老师布置网课时必须同时写清课程入口、具体章节或分 P、观看目的、跳过范围和观看后的验收题。观看后的验收不是复述视频目录，而是：

1. 用自己的话解释当前源码解决了什么问题；
2. 预测一个参数或地址变化；
3. 说出一个失败边界和证据；
4. 把结论映射到我们的内核。

四项中有一项缺失，资料状态保持“需补课”，不增加新视频。

## 五、笔记协议

平板笔记只需要保留：

- 【重点】：必须课后复述；
- 【易错】：一个常见误解和反例；
- 一个自己的图或例子；
- 一个实际命令/输出；
- 一个还不确定的问题。

整理后的摘要放在 notes/lesson-log/，入口登记在 notes/INDEX.md。模板见 source-track/UNIT_TEMPLATE.md 和 notes/NOTE_TEMPLATE.md。

## 六、作业批改

老师按以下顺序批改：

1. 是否完成当前出口；
2. 理由是否说明因果，而不是只报最终值；
3. 源码定位是否准确，边界和错误路径是否考虑；
4. 命令、环境和日志是否足以复现；
5. 一处改动是否真的产生了可解释差异；
6. 迁移题能否在新参数、新设备或新调用顺序下成立。

统一标签：

~~~text
✓ 已掌握       ↺ 需要巩固       ! 概念更正
E 未验证       R 已完成迁移题   G 已通过阶段 Gate
~~~

答对一道题只更新该题；只有在变体题和口头复述中仍然正确，才更新能力等级。

## 七、记录和 Git 推送

每个源码单元完成后更新：

| 记录 | 必须包含 | 文件 |
|---|---|---|
| 单元记录 | 目标、源码、预测、命令、改动、故障、批改、下一步 | notes/lesson-log/YYYY-MM-DD-SF-xx-topic.md |
| 笔记索引 | 单元链接、状态、待复习项 | notes/INDEX.md |
| 能力状态 | 已验证能力、未验证能力、补强项、当前指针 | notes/PROGRESS.md |
| 运行证据 | 原始日志、QEMU 参数、反汇编、故障结果 | evidence/SF-xx-* |
| 迁移说明 | 外部机制如何变成自研接口 | 单元记录中的“与我们的 OS 映射” |

学习进度提交只包含学习区相关文件，并使用能说明主题的 commit message，例如 lesson(SF-01): trace xv6 boot path。第三方源码不提交到仓库，访问凭据和本机私有路径不进入记录。

学习进度按仓库既定流程推送到 GitHub；实际推送前检查 git diff --check、敏感信息和待提交文件范围。产品区的代码或证据若不是本单元产物，不随学习记录一起提交。

## 八、状态和边界

当前状态只在 notes/PROGRESS.md 保留一个指针，例如 SF-00/进行中。历史 C-PRE 课次仍可追溯，但标记为历史前置，不阻挡 SF 主线。

产品区的 G0–G10/M0–M14 证据和学习区的 SF Gate 分开统计：

~~~text
产品证据：证明某个 checkout 的工程切片曾经运行
学习证据：证明学员能解释、改动、复现和迁移该机制
~~~

只有两类证据都满足各自标准，才讨论把学习实验迁移为产品成果。
